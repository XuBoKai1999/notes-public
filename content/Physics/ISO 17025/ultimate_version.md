# ISO/IEC 17025：終極版講義

### 以 ISO/IEC 17025:2017 Training Material ＋前面題庫考點為主

這版定位不是「把 170 頁 PPT 再抄一遍」，而是：

> **理解版 + 條號版 + 考試版 + Open Book 查表版**

你真正要理解的是一件事：

> **ISO/IEC 17025 是一套用來證明「實驗室有能力，而且其結果可信」的管理與技術制度。**

整份標準幾乎都可以放進這個流程：

$$
\boxed{
\text{公正的人}
+\text{適當資源}
+\text{正確方法}
+\text{可追溯量測}
+\text{完整紀錄}
+\text{持續監控}
\Rightarrow
\text{可信結果}
}
$$

教材本身也是以第 4～8 章作為整套系統骨架：一般要求、架構、資源、過程、管理系統。

------

# 0. 整套 17025 一張表

| 章    | 名稱         | 它在問什麼？     | 記憶詞                      |

> **第 6 章：你憑什麼有資格量。**

> **第 7 章：你到底怎麼量。**

> **第 8 章：你怎麼確保以後也一直量得對。**

# 1. 先把術語一次弄懂

這部分題庫很容易用字義混淆你。

| 名詞                                     | 意義                                                       | 最簡記法                   |
| ---------------------------------------- | ---------------------------------------------------------- | -------------------------- |
| **Verification 查證／驗證**              | 以客觀證據證明已滿足指定要求                               | **我做得對不對？**         |
| **Validation 確效／確認**                | 證明方法適合預定用途                                       | **這方法適不適合這樣用？** |
| **Decision Rule 判定規則**               | 判斷結果是否符合規格的規則                                 | 怎樣算 PASS？              |
| **Statement of Conformity 符合性聲明**   | 合格／不合格、符合／不符合                                 | 最後的判決                 |
| **Calibration 校正**                     | 建立標準量值與儀器指示值間之關係，再利用此關係得到量測結果 | 標準 ↔ 指示值              |
| **Measurement 量測**                     | 以實驗方式得到量值的過程                                   | 得到數值                   |
| **Test 測試**                            | 按規定程序測定產品／過程／服務特性                         | 看某特性                   |
| **Sampling 採樣**                        | 從母體取部分樣本以進行後續判斷                             | 抽代表樣本                 |
| **Metrological Traceability 計量追溯性** | 透過文件化、不間斷校正鏈連到適當參考標準                   | 一路追回標準               |

教材在第 14～18 頁即先集中解釋 Verification、Validation、Decision Rule、校正、量測、測試、採樣與計量追溯等術語。

# 2. Verification 與 Validation：必懂

這大概是整份標準最值得帶走的概念之一。

假設 CNS 已經規定一種電阻校正法。

你把方法搬進自己的實驗室。

## Verification

問題是：

> **我們實驗室真的有能力正確執行它嗎？**

因此你要證明：

- 儀器夠不夠
- 人員會不會
- 精密度是否達標
- 結果是否符合方法性能

也就是：

> **已有方法 → 證明我們能做。**

------

## Validation

如果你：

- 自己發明方法
- 修改標準方法
- 使用非標準方法
- 超出標準方法原定範圍

那就要回答：

> **這個方法真的適合我要做的用途嗎？**

教材 7.2.2 特別要求非標準、自行制定、超出預定範圍或修改後的標準方法進行確認。

### 一句英文直接記

> **Verification = Did I do it right?**
> **Validation = Am I doing the right thing?**

------

# 3. 第 4 章：一般要求

## 4.1 公正性 Impartiality

### 核心

> **結果不能被不當壓力影響。**

可能來源：

| 來源 | 例子               |
| ---- | ------------------ |
| 商業 | 大客戶威脅取消訂單 |
| 財務 | PASS 才有獎金      |
| 人際 | 樣品是主管朋友的   |
| 組織 | 母公司要求改結果   |
| 行銷 | 業務承諾一定會合格 |

標準要求不只是「不要作弊」。

而是：

**管理階層承諾公正**
→
**持續識別公正性風險**
→
**有風險就消除或降低**
→
**能證明自己做過**

教材明確將公正性分成管理階層承諾、不受商業財務壓力影響、持續辨識風險，以及消除或降低風險。

### 題庫陷阱

「實驗室應持續監控**員工的公正性**」這種說法要小心。

標準核心用語是：

> **持續識別其公正性的風險。**

不是簡單規定「持續監控每位員工」。

------

# 4.2 保密性 Confidentiality

原則：

> **實驗室活動中取得或產生的客戶資訊應保密。**

包含：

- 顧客資訊
- 測試結果
- 校正資料
- 樣本資料
- 從投訴者得到的資訊
- 從主管機關得到的資訊

特殊情況：

### 法律要求揭露

可以揭露。

但：

> **原則上要通知客戶或相關個人。**

除非：

> 法律禁止你通知。

另外，外部人員、委員會、承包商等若接觸資料，也要保密。

### 4 章記憶

> **4 = 不偏、不洩。**

------

# 4. 第 5 章：架構要求

第 5 章不是在管量測技術，而是在防止：

> 「出了問題不知道誰負責。」

------

## 5.1 法律實體

實驗室必須：

> 是法律實體，或法律實體中明確界定的一部分。

也就是要有：

> **法律責任歸屬。**

例如：

- 公司
- 政府機關
- 大學
- 研究機構中的實驗室

------

# 5.2 最高管理階層

必須確定：

> **誰對實驗室全權負責。**

例如：

- 實驗室主任
- 實驗室負責人
- 經授權的管理者

------

# 5.3 活動範圍

實驗室要明確寫出：

> **我們到底宣稱自己能做哪些活動？**

例如：

- DC Voltage Calibration
- Resistance Calibration
- EMF Testing

不能：

> 自己其實沒有能力做，全部外包，然後還宣稱那是自己的 17025 能力。

------

# 5.4 活動場所

17025 不只管固定實驗室。

也可能發生在：

- 固定實驗室
- 外部測試場
- 臨時設施
- 移動式實驗室
- 客戶現場

核心：

> **換地點不能把品質要求丟掉。**

------

# 5.5～5.7 組織與權責

需要明確：

- 組織結構
- 管理關係
- 技術關係
- 支援服務
- 人員職責
- 權限
- 代理
- 管理系統變更後如何保持完整性

教材前段以「法律主體、組織圖、全權負責管理階層、授權書、職責」概括第 5 章。

### 第 5 章一句話

> **誰是誰、誰能幹嘛、誰負責。**

------

# 5. 第 6 章：資源要求

記這五個字：

> # **人、環、機、溯、外**

教材的架構圖也是按照人員、設施、設備、計量追溯及外部供應展開。

------

# 6.2 人員

這也是題庫高頻。

核心不是：

> 上過課。

而是：

> **有能力，而且有證據證明有能力。**

實驗室必須規定相關能力要求，例如：

| 能力來源 | 可能內容   |
| -------- | ---------- |
| 學歷     | 相關學科   |
| 資格     | 特定證照   |
| 培訓     | 儀器、方法 |
| 技術知識 | 方法原理   |
| 技能     | 實際操作   |
| 經驗     | 工作經驗   |

還要建立：

> **遴選 → 訓練 → 監督 → 考核 → 授權 → 持續監控能力**

### 超重要陷阱

ISO 17025 **沒有簡單規定「每 X 年一定訓練一次」**。

它要求的是：

> 確保能力並保留適當紀錄。

所以看到：

> 「ISO 17025 規定人員每年一定要接受一次教育訓練。」

通常就要高度懷疑。

------

# 6.2.6 授權

某人「會做」不等於：

> **有權正式執行。**

尤其像：

- 方法開發
- 方法驗證／確認
- 分析結果
- 符合性聲明
- 意見解釋
- 報告審查
- 報告批准

都可能需要正式授權。

------

# 6.3 設施與環境條件

原則：

> **環境不得讓結果失效。**

可能影響因素：

| 類型 | 例子         |
| ---- | ------------ |
| 熱   | 溫度         |
| 水氣 | 濕度         |
| 電磁 | EMI          |
| 機械 | 振動         |
| 聲學 | 聲音         |
| 污染 | 灰塵、微生物 |
| 輻射 | 電離／非電離 |
| 電氣 | 供電品質     |

如果環境會影響結果：

> **監測 + 控制 + 記錄。**

不是所有房間都必須維持教材舉例的特定溫濕度。

真正判斷基礎是：

> **方法、規範或結果有效性是否需要。**

------

# 6.4 設備

設備範圍比一般人想得大。

包括：

- 儀器
- 量具
- 測量標準
- 參考物質
- 標準品
- 試劑
- 消耗品
- 軟體
- 輔助設備

------

## 6.4.2 非長期控制設備

例如：

> 借別人的儀器。

不是說不是你的就不管。

使用前仍要：

> **確保符合要求。**

------

# 6.4.3～6.4.4 使用與投入服務

需要適當的：

> 處理、運輸、儲存、使用、維護。

投入使用／重新使用前：

> **確認符合規定要求。**

------

# 6.4.5 設備能力

設備必須達到：

> **所需準確度／測量不確定度。**

不是：

> 「這台表很貴，所以應該可以。」

------

# 6.4.6 哪些設備需要校正？

當：

### A.

準確度或量測不確定度會影響報告結果有效性。

或

### B.

建立計量追溯性需要它。

就要校正。

------

# 6.4.7 校正方案

實驗室要有：

> **Calibration Program**

並且：

> 定期檢討、必要時調整。

所以校正週期不是天上掉下來的固定神諭。

------

# 6.4.8 校正狀態

需要校正或有有效期的東西：

> 使用者應能快速判斷目前狀態。

常見：

- CAL DATE
- DUE DATE
- 設備編號
- 狀態標示

------

# 6.4.9 設備出包

如果：

- 超載
- 掉落
- 處理不當
- 出現可疑結果
- 故障
- 超出規定限值

處理流程：

**停止使用**
→
**隔離／清楚標示**
→
**確認恢復正常**
→
**分析舊結果有沒有受影響**
→
**必要時啟動 7.10 不符合工作**

這裡很重要：

> **不能只修機器，還要追舊結果。**

------

# 6.4.10 期間核查 Intermediate Check

校正週期還沒到，不代表什麼都不用管。

必要時：

> 在兩次正式校正之間做期間核查。

目的：

> **維持對設備性能的信心。**

------

# 6.4.11 修正值

校正報告若給：

> Correction / Correction Factor

不能收起來就算了。

如果適用：

> **必須更新並正確應用。**

------

# 6.4.12 防止意外調整

例如：

- 儀器設定權限
- 密碼
- 封條
- 軟體權限
- Excel 鎖公式

教材甚至直接以 Excel 計算式鎖定作為資訊與設備控制的例子。

------

# 6.4.13 設備紀錄

常見必備內容：

- 設備識別
- 廠商
- 型號
- 序號
- 軟體／硬體版本
- 位置
- 校正紀錄
- 驗收準則
- 維護
- 損壞
- 故障
- 維修
- 修改

題庫問：

> 「設備要不要保存紀錄？」

答案幾乎不用想：

> **要。**

------

# 6.5 計量追溯性

這是校正實驗室的中心。

正式概念：

> **量測結果透過文件化、不間斷的校正鏈，與適當參考標準相連；鏈上每一次校正都對量測不確定度有貢獻。**

典型：

$$
\boxed{
DUT
\rightarrow
Working\ Standard
\rightarrow
Reference\ Standard
\rightarrow
National\ Standard
\rightarrow
SI
}
$$

### 重點

> **追溯的是量測結果，不只是那台儀器。**

------

# 6.5.2 追溯至 SI 的方式

教材列出三類：

| 方法                     | 例子           |
| ------------------------ | -------------- |
| 有能力實驗室提供校正     | 認證校正實驗室 |
| 有能力 RM 生產者提供 CRM | ISO 17034      |
| SI 單位直接實現          | 基本單位實現   |



------

# 6.5.3 無法追至 SI 怎麼辦？

有些量沒有實際可行的 SI traceability。

那可以使用：

- CRM
- 參考測量程序
- 規定方法
- 清楚描述並經適當比較證實的 consensus standard

重點：

> **仍然要有合理且可信的參考來源。**

------

# 6.6 外部產品與服務

不要以為：

> 「這是廠商的錯，跟實驗室無關。」

只要它會影響你的實驗室活動，就要管理。

例如：

| 產品     | 服務     |
| -------- | -------- |
| 標準物質 | 校正     |
| 儀器     | 維修     |
| 試劑     | PT       |
| 耗材     | 採樣     |
| 量測標準 | 外包測試 |

需要：

> **選擇 → 評價 → 監督 → 重新評價。**

而且要明確溝通：

- 要買什麼
- 驗收標準
- 人員資格
- 需要的能力

------

# 6. 第 7 章：過程要求

這是整份標準最大的核心。

教材第 10 頁把它很漂亮地串成：

> 顧客 → 方法 → 採樣 → 樣本 → 技術紀錄 → MU → 品保 → 報告 → 抱怨 → 不符合 → 資料管理。

可以直接當成：

# 「一份校正案的一生」

------

# 7.1 要求、標書與合約審查

工作開始前先回答：

> **客戶要什麼？**

> **我們做得到嗎？**

> **有設備嗎？**

> **有方法嗎？**

> **方法對嗎？**

------

## 客戶方法不適合？

如果客戶要求的方法：

- 不適當
- 過時

應：

> **通知客戶。**

------

# 外包／轉包

如果要由外部供應者做：

要：

> 符合 6.6。

而且：

> 通知客戶，並取得客戶同意。

------

# 7.1.3 Decision Rule

假設客戶說：

> 「我要知道這個 10.000 V 標準是否合格。」

這已經不只是：

> 告訴他量到多少。

而是：

> **做符合性聲明。**

所以要先確定：

> **判定規則。**

如果規範本身已寫好：

> 按規範。

否則：

> 與客戶溝通並取得同意。

------

# 7.2 方法選擇、Verification、Validation

這一章題庫很愛。

------

## 7.2.1 方法來源

可能包括：

1. 國際／區域／國家標準
2. 技術組織方法
3. 書籍／期刊方法
4. 製造商方法
5. 自行開發方法
6. 修改方法

原則：

> **優先使用適當且現行有效的方法。**

------

# 7.2.1.5 Verification

新方法引入實驗室前：

> 要證明自己可以正確運用。

方法被修訂：

> 必要程度上重新 Verification。



------

# 7.2.1.7 偏離方法

如果要偏離標準方法：

不能偷偷改。

需要：

> **文件化 + 技術判斷 + 授權 + 客戶接受**

------

# 7.2.2 Validation

以下通常需要：

- 非標準方法
- 自行開發
- 修改標準方法
- 超出原用途範圍

可能用：

- CRM
- 偏倚
- 精密度
- robustness
- 方法比較
- ILC
- uncertainty

來證明適用。

------

# 7.3 採樣 Sampling

如果實驗室負責採樣：

必須：

> **有 sampling plan + sampling method。**

尤其要確保：

> 後續結果具有代表性、有效性。

------

# 採樣紀錄

至少要能還原：

| 問題     | 內容       |
| -------- | ---------- |
| 怎麼採   | 方法       |
| 何時採   | 日期、時間 |
| 採什麼   | 樣本       |
| 誰採     | 人員       |
| 用什麼   | 設備       |
| 在哪     | 地點       |
| 當時環境 | 條件       |
| 有無異常 | 偏離       |

一句話：

> **人、事、時、地、物。**

------

# 7.4 測試／校正物品處理

樣品從進實驗室到出去，整條 chain of custody 都要顧。

包括：

> 運送 → 接收 → 處置 → 保護 → 儲存 → 保留 → 清理／返還

目的：

> 防止變質、污染、損壞、丟失、搞混。

------

## 樣品唯一識別

一定要避免：

> A 客戶的東西被當成 B 客戶。

所以要有：

> **唯一識別系統。**

------

## 收到時已異常

例如：

- 包裝破損
- 溫度不符
- 樣品狀態不明
- 描述不一致

要：

> 先記錄。

必要時：

> 詢問客戶。

如果客戶堅持做：

> 報告可能要加免責說明，表示偏離可能影響結果。

------

# 7.5 技術紀錄

這是我認為整套制度最好的規定之一。

目標：

> **讓其他人日後能盡可能在接近原始條件下重建這次工作。**

所以應包含：

- 原始觀察
- 原始數據
- 計算
- 日期
- 人員
- 測試條件
- 儀器
- 結果

------

# 什麼時候記？

> **取得資料時就記。**

不是：

> 下班前靠記憶補。

------

# 7.5.2 修改紀錄

可以修。

但要：

> **保留原始資訊的可追溯性。**

要知道：

- 原來是什麼
- 改成什麼
- 誰改
- 何時改

### 題庫陷阱

「原始記錄錯誤後，可以刪除原紀錄並重新製作。」

通常：

> **錯。**

可以更正，但不能讓原始狀態消失。

------

# 7.6 量測不確定度 MU

## 核心

實驗室要：

> **識別所有顯著的不確定度貢獻。**

包括適用時：

> 採樣的不確定度。

------

# A 類與 B 類

### Type A

由：

> **重複觀測的統計分析**

例如平均值、標準差。

------

### Type B

由：

> **其他資訊**

例如：

- Calibration Certificate
- 儀器 specification
- resolution
- previous data
- reference data

------

# 標準不確定度

各來源最後要轉成：

$$
u_i
$$

------

# 組合標準不確定度

典型獨立輸入：

# $$ u_c

\sqrt{
\sum_i
\left$
c_i u_i
\right$^2
}
$$

其中：

$$
c_i=\frac{\partial y}{\partial x_i}
$$

------

# 擴充不確定度

$$
\boxed{
U=k u_c
}
$$

教材以常見 95% 信心水準、$k=2$ 作為教學例子。

------

# 校正 vs 測試

## 校正實驗室

教材 7.6.2：

> **所有校正應評估測量不確定度。**

## 測試實驗室

也應評估。

若方法特性使嚴格評定困難：

> 可以依理論理解與實際經驗評估。

------

# 不確定度的考試心法

不要看到：

> 標準差

就直接等於：

> 量測不確定度。

標準差通常只是：

> **其中一個 uncertainty component。**

真正結果還可能包含：

- Reference Standard
- Resolution
- Repeatability
- Environment
- Correction
- Drift
- Method

------

# 7.7 確保結果有效性

這就是：

> # Quality Assurance

實驗室不能只說：

> 「我昨天校正過，所以我今天一定量得對。」

還要持續監控結果。

------

# 7.7.1 實驗室內監控

方法可能包括：

| 方法                | 意義             |
| ------------------- | ---------------- |
| CRM/QC              | 已知物質         |
| 校準設備            | 與可追溯設備比較 |
| 功能核查            | 設備是否正常     |
| Control Chart       | 看 drift         |
| Intermediate Check  | 期間核查         |
| Repeat              | 重複量           |
| Different Method    | 不同方法交叉     |
| Internal Comparison | 人員／設備比對   |
| Blind Sample        | 盲樣             |
| Report Review       | 查報告           |

------

# 7.7.2 實驗室間

兩大類：

### PT — Proficiency Testing

能力試驗。

------

### ILC — Interlaboratory Comparison

實驗室間比對。

PT 可以視為具有能力評估目的的一類實驗室間比較。

------

# QC vs Calibration

| Calibration                  | QC                 |
| ---------------------------- | ------------------ |
| 建立量值關係                 | 持續看系統有沒有漂 |
| 一次校正活動                 | 長期監控           |
| 建立 traceability 的重要工具 | 證明結果持續有效   |

------

# 7.7.3 結果超標

如果 QC／PT／監控結果：

> 超出預定準則。

不能：

> 「下個月再看看。」

應：

> 採取適當措施，避免發出錯誤結果。

------

# 7.8 報告結果

結果送出去前：

> **要審查與批准。**

要求：

> 準確、清晰、明確、客觀。

------

# 7.8.2 一般報告內容

教材列了很多項目，考試不用硬背 17 個字母，但知道邏輯：

### 誰？

- 實驗室
- 客戶
- 批准人

### 什麼？

- 樣品
- 方法
- 結果

### 何時？

- 收樣
- 採樣
- 測試
- 發報告

### 哪裡？

- 實驗室活動地點

### 如何？

- 方法
- 偏離
- 外包結果

### 唯一性？

- Report No.
- Page x of y

------

# 7.8.3 測試報告額外內容

必要時：

- 環境條件
- 符合性聲明
- 量測不確定度
- 意見解釋
- 法規／客戶要求

------

# 7.8.4 校正證書特定要求

這對你比較重要。

校正證書還要包含：

| 項目             | 重點               |
| ---------------- | ------------------ |
| **MU**           | 測量結果的不確定度 |
| 環境             | 若影響結果         |
| **Traceability** | 如何建立計量追溯   |
| Before / After   | 有調校時           |
| Conformity       | 適用時             |
| Opinions         | 適當時             |



------

# 一個經典考點

> **校正證書或校正標籤原則上不得自行推薦校正間隔。**

例外：

> **客戶同意。**

這個很適合出是非題。

------

# 7.8.6 符合性聲明

如果報告：

> PASS

就要說清楚：

### 哪個結果？

### 符合哪個規範？

### 用什麼 Decision Rule？

同時要考慮判定規則相關：

> False Accept / False Reject risk。

除非：

> 客戶、法規或規範本身已經指定判定規則。

------

# 7.8.8 修改報告

不能 Word 打開改一下再寄出去當沒事。

要求：

> 修改具有識別性與追溯性。

要知道：

- 修改了什麼
- 為什麼改
- 原報告是哪個
- 新報告是哪個
- 新報告替代誰

------

# 7.9 抱怨 Complaints

實驗室必須有：

> **文件化的抱怨處理流程。**

流程概念：

> 接收 → 確認 → 調查 → 決定 → 措施 → 追蹤 → 回覆

重要：

> 對抱怨結果做出決定或審查批准的人，應盡可能與原涉及活動無關。

目的：

> 防止自己查自己、自己宣布自己完全沒錯。

------

# 7.10 不符合工作 Nonconforming Work

非常高頻。

什麼叫不符合？

例如：

- 溫度超限
- 儀器過期
- QC Fail
- 用錯 SOP
- 樣品搞錯
- 計算錯
- 報告錯
- 設備故障

$$
\text{發現問題}
$$

\text{控制問題}
$$

↓

## 8.7 矯正措施

問：

> **為什麼會出包？怎樣讓它不要再發生？**

所以：

> **7.10 = 控制事件。**

> **8.7 = 消除原因。**

# 7.11 資料控制與資訊管理

可以是：

- LIMS
- Database
- Excel
- 自製程式
- 紙本系統

------

# 系統投入使用前

要：

> **功能確認。**

尤其修改：

- 軟體
- configuration
- calculation
- interface

後：

> 要適當驗證。

# 資料系統必須防止

- 未授權存取
- 未授權修改
- 遺失
- 破壞
- 資料完整性受損

還需要：

# Excel 是非常好的考題來源

教材直接提到：

> Excel 計算式應考慮鎖定、授權與定期檢查。

例如你把公式：

```text
=A1*B1
```

誤改成：

```text
=A1+B1
```

結果一百份校正報告全錯。

這完全屬於 17025 要管理的問題。

## Option A

# 8.2 管理系統文件

- 公正性
- 一致運作
- 文件

- 系統
- 紀錄

相關人員應：

> 能取得與自己職務相關的文件。

# 8.3 文件控制

## Document 是什麼？

例如：

- SOP
- Policy
- Specification
- Manual
- Drawing
- Software
- Notice
- Form Template

# 文件要管什麼？

### 發行前批准

### 定期審查

### 必要時更新

### 有版本

### 有唯一識別

### 使用地點拿得到正確版本

### 舊版不能誤用

------

# 8.3 vs 8.4

這是超級高頻。

|      | 文件 Document   | 紀錄 Record      |
| ---- | --------------- | ---------------- |
| 定義 | 告訴你應怎麼做  | 證明實際做了什麼 |

| 核心 | Version Control | Evidence         |

## 最短記法

> **文件 = 規則。**

> **紀錄 = 證據。**

# 8.4 紀錄控制

紀錄要管理：

- 識別
- 儲存
- 保護
- 備份
- 歸檔
- 檢索
- 保存期
- 處置

而且：

教材的實務範例提到紙本／數位、調閱權限及完整紀錄管理。

# 8.5 風險與機會

目的不是做漂亮的風險矩陣。

真正目的：

> **預先知道哪裡可能出問題，並採取相稱措施。**

目的包括：

- 確保系統預期結果
- 增加達成目標機會
- 預防失效
- 降低不利影響
- 改進

------

# 是否一定要 FMEA？

教材明確指出：

> 標準**沒有強制要求正式風險管理方法**。

實驗室可以自行決定方法。

所以看到：

> 「ISO 17025 強制實驗室使用 FMEA。」

不對。

# 8.6 改進

注意：

> **改進不代表之前有錯。**

可能來自：

- 員工建議
- 客戶回饋
- 資料分析
- PT
- 管審
- 稽核
- 風險分析

# 8.7 矯正措施 Corrective Action

這是題庫核心。

流程：

$$
\text{不符合}
$$

↓

$$
\text{控制／改正}
$$

↓

$$
\boxed{\text{找 Root Cause}}
$$

↓

$$
\text{消除原因}
$$

↓

$$
\text{避免再發}
$$

↓

$$
\text{確認措施有效}
$$

↓

$$
\text{必要時改管理系統／更新風險}
$$

教材明確要求分析不符合、確認原因、確認是否可能存在類似問題，再實施並評估矯正措施有效性。

------

# Correction vs Corrective Action

假設溫度計壞了。

### Correction 改正

> 買新的溫度計。

### Corrective Action 矯正措施

調查發現：

> 原來沒有任何人負責 periodical check。

於是：

> 新增設備責任人 + check schedule + alarm。

這才是在：

> **消除 root cause。**

------

# 8.8 內部稽核 Internal Audit

問題：

> **我們有沒有照自己的制度和 ISO 17025 做？**

不是：

> 「主管覺得大家工作很好。」

而是有系統地查：

- 是否符合自身系統
- 是否符合 17025
- 是否有效實施

------

# 多久稽核一次？

題庫很可能會陰你。

ISO 的說法：

> **按照策劃的時間間隔。**

而不是直接規定：

> 一年一次。

實驗室自己要規劃頻率，而且考慮：

- 活動重要程度
- 變更
- 上次稽核結果

教材 8.8 也是使用「按照策劃的時間間隔」，並要求規劃頻率、方法、職責、範圍與報告。

------

# 8.9 管理審查 Management Review

這是整套制度的最高層級 review。

不是在問：

> 某一份報告有沒有填錯。

而是：

> **我們整套品質系統還適宜嗎？充分嗎？有效嗎？**

| 人       | 員工回饋          |

| 改善     | Improvement       |

至少要對：

1. 管理系統有效性

作出決策或措施。

# 11. 其實整套 ISO 17025 就是這個 Workflow

把所有條文放回實際工作，就非常合理了：

```text
            公正 + 保密
                 │
                 ▼
          定義組織與權責
                 │
                 ▼
     人員 + 環境 + 設備 + 追溯
                 │
                 ▼
        接受客戶委託／合約
                 │
                 ▼
             選擇方法
          ┌──────┴──────┐
          │             │
   Verification      Validation
          │             │
          └──────┬──────┘
                 ▼
          採樣／接收物品
                 │
                 ▼
              做量測
                 │
          ┌──────┴──────┐
          ▼             ▼
       原始紀錄       計算 MU
          │             │
          └──────┬──────┘
                 ▼
        QC / PT / ILC
                 │
                 ▼
            審查結果
                 │
                 ▼
             發出報告
                 │
        ┌────────┴────────┐
        ▼                 ▼
      正常              出問題
                          │
                  Nonconforming
                          │
                    評估舊結果
                          │
                     Root Cause
                          │
                 Corrective Action
                          │
                        改進
```

最上面再罩一層：

```text
Document Control
Record Control
Risk Management
Internal Audit
Management Review
```

所以你前面說它其實是一套很好用的工程流程，這個觀察是對的：**17025 不是一堆互不相干的行政規定，而是一條完整的「可信結果生產鏈」。**

## 整份標準最後壓成一句

> **先確保人與組織公正可靠，給他們適當的人力、環境、設備與可追溯標準，再以受控的方法完成工作、留下足以重建的紀錄、評估不確定度並持續驗證結果有效性；最後用文件控制、風險管理、異常處理、矯正措施、內部稽核與管理審查，確保整個系統長期可信。**

這就是 **ISO/IEC 17025:2017**。

下一層「原始條文版」就不應再像講義，而應該做成**條號 → 原始要求摘要 → 關鍵字 → 題庫陷阱**的查閱手冊，專門給 Open Book 考試用；和這份終極理解版用途不同。
