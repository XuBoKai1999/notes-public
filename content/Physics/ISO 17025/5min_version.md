# ISO/IEC 17025：5 分鐘極速版

## 0. 先只記住一句話

**ISO 17025 = 規定一個實驗室怎樣證明自己「有能力，而且量出來的結果可信」。**

整份標準其實就是在回答：

> **誰來量？拿什麼量？怎麼量？怎麼證明量得對？出問題怎麼辦？**

真正內容集中在 **4～8 章**。

| 章             | 一句話                                     |
| -------------- | ------------------------------------------ |
| **4 一般要求** | 不准亂搞：**公正、保密**                   |
| **5 結構要求** | 誰負責什麼要講清楚                         |
| **6 資源要求** | **人、環境、設備、追溯性、外部供應**要可靠 |
| **7 過程要求** | **從接案一路到出報告**怎麼做               |
| **8 管理系統** | 文件、紀錄、稽核、改善怎麼管               |

其中：

> **6 = 你憑什麼有能力量。**
> **7 = 你實際怎麼量。**
> **8 = 你怎麼確保這套東西長期不爛掉。**

------

# 1. 第 4 章：一般要求

只有兩個大觀念：

### 4.1 公正性

實驗室不能因為：

- 客戶施壓
- 老闆施壓
- 商業利益
- 財務利益
- 人際關係

而改變結果。

而且不是「我覺得自己很公正」就好，而是要**持續識別公正性風險**，有風險就要消除或降低。

### 4.2 保密

客戶資料、結果等原則上都要保密。

但如果**法律要求必須揭露**，可以揭露；通常應通知客戶，除非法律禁止通知。

**記憶：第 4 章 = 不偏、不洩。**

------

# 2. 第 5 章：結構要求

這章沒什麼物理，就是組織管理。

實驗室必須是：

> **可以被法律識別、有人負責、有明確權責的組織。**

要知道：

- 誰是管理者
- 誰負責什麼
- 誰有什麼權限
- 組織彼此關係
- 怎麼確保管理系統正常運作

**記憶：第 5 章 = 誰負責？**

------

# 3. 第 6 章：資源要求

這章非常重要。

直接記：

> **人、場、機、溯、外**

| 條文 | 東西           | 核心                     |
| ---- | -------------- | ------------------------ |
| 6.2  | 人員           | 人要有能力               |
| 6.3  | 設施與環境     | 環境不能搞壞結果         |
| 6.4  | 設備           | 儀器要適用、維護、校正   |
| 6.5  | 計量追溯性     | 結果要能一路追到參考標準 |
| 6.6  | 外部產品與服務 | 外包/採購也要管          |

### 人員

不是「有這個人」即可，而是：

> **要證明他有能力做這件事。**

例如教育、訓練、經驗、技能、資格認定、授權。

### 環境

例如：

- 溫度
- 濕度
- 振動
- 灰塵
- EMI
- 電源

只要會影響結果，就要控制/監測。

### 設備

設備必須：

> **適合用途，而且不可以讓結果失效。**

該校正就校正、該維護就維護，而且要有紀錄。

### 計量追溯性

這是計量實驗室核心概念：

> **你的量測結果可以透過一條有文件的不間斷校正鏈，追溯到適當的參考。**

最典型就是：

**你的儀器 → 上級標準 → 國家標準 → SI**

但別把「追溯」單純理解成「送校過就好」。

------

# 4. 第 7 章：過程要求

**最大章，也是考試最值得查的一章。**

你可以把它理解成一個工件進實驗室：

> 客戶來了
> ↓
> 確認他要什麼
> ↓
> 決定怎麼量
> ↓
> 收到樣品
> ↓
> 開始量
> ↓
> 評估結果可信度
> ↓
> 出報告
> ↓
> 客戶有問題再處理

對應：

| 條號     | 關鍵字                 |
| -------- | ---------------------- |
| **7.1**  | 要求、標書、合約審查   |
| **7.2**  | 方法的選擇、驗證、確認 |
| **7.3**  | 採樣                   |
| **7.4**  | 測試/校正物品處理      |
| **7.5**  | 技術紀錄               |
| **7.6**  | **量測不確定度**       |
| **7.7**  | **確保結果有效性**     |
| **7.8**  | **結果報告**           |
| **7.9**  | 抱怨                   |
| **7.10** | 不符合工作             |
| **7.11** | 資料與資訊管理         |

------

## 5. 7.1 合約審查

接工作前要確認：

> **客戶到底要什麼？我們做不做得到？方法對不對？**

如果客戶指定的方法**不適當或過時**，實驗室要通知客戶。

如果客戶要你判：

> PASS / FAIL

那就是**符合性聲明**，要有明確的**判定規則（decision rule）**，而且通常要跟客戶溝通並取得同意。

------

# 6. 7.2 方法：驗證 vs 確認

這兩個很容易考。

### 驗證 Verification

> **證明你能正確執行既有方法。**

例如標準方法已經存在，我證明我們實驗室做得出來。

### 確認 Validation

> **證明這個方法適合預定用途。**

特別是：

- 非標準方法
- 實驗室自行開發方法
- 超出原本適用範圍的方法
- 修改過的標準方法

所以：

> **Verification：我會不會做。**
> **Validation：這方法能不能這樣用。**

------

# 7. 7.6 量測不確定度

你剛才已經速通過這部分，這裡只留一句：

> **量測值不是神諭，要描述結果合理可能散布到哪裡。**

典型：

[
y \pm U
]

而

[
U=k u_c
]

GUM 說 expanded uncertainty 是 combined standard uncertainty (u_c) 乘 coverage factor (k)，常見 (k) 約為 2～3。

在你們校正實驗室尤其重要：

> **校正基本上一定要評估量測不確定度。**

------

# 8. 7.7 確保結果有效性

不是校正完就相信自己。

還要持續確認：

> **「我的系統現在還量得對嗎？」**

例如：

- QC / check standard
- control chart
- 重複測試
- proficiency testing
- interlaboratory comparison

你們實際工作中的 control chart 就是典型例子：例如低電流系統會持續量 check unit，建立平均值、標準差以及 UCL/LCL 來監控系統。

所以：

> **Calibration 解決「儀器準不準」的一部分問題；
> QC 解決「整套系統現在是否仍正常」。**

------

# 9. 7.8 報告

結果最後必須：

> **準確、清楚、客觀，而且包含理解結果所需要的資訊。**

檢測報告與校正證書有不同額外要求。

有一個很好考的小陷阱：

> **校正證書原則上不能自己推薦下次校正週期。**

除非已經跟客戶約定。教材在 7.8.4.3 就直接寫了這點。

------

# 10. 7.9 / 7.10：抱怨與出包

### 客戶抱怨

不能：

> 「知道了，謝謝指教。」

然後丟垃圾桶。

必須有正式流程：

**收到 → 評估 → 調查 → 決定 → 回覆 → 留紀錄**

### 不符合工作

例如：

> 「幹，昨天那台標準器其實過期了。」

這就是**不符合工作**。

不是偷偷補校正就好。

要：

> **停／控制問題 → 評估影響 → 看以前結果有沒有被影響 → 必要時通知客戶 → 決定是否恢復工作。**

這個思維非常重要。

------

# 11. 第 8 章：管理系統

這章可以理解成：

> **怎樣避免整個實驗室隨著時間逐漸腐化。**

Option A 包含：

| 條號 | 關鍵字       |
| ---- | ------------ |
| 8.2  | 管理系統文件 |
| 8.3  | 文件控制     |
| 8.4  | 紀錄控制     |
| 8.5  | 風險與機會   |
| 8.6  | 改進         |
| 8.7  | **矯正措施** |
| 8.8  | **內部稽核** |
| 8.9  | **管理審查** |

教材也明確列出這組架構。

### 文件 vs 紀錄

這個要分清楚：

> **文件 = 告訴你「應該怎麼做」。**
> **紀錄 = 證明你「當時真的怎麼做」。**

例如：

**SOP → 文件**

**今天 E08 的校正原始數據 → 紀錄**

------

# 12. 矯正措施不是「修好」

這也是常見混淆。

假設：

> 儀器壞了。

把儀器修好：

**改正（correction）**

但如果問題是「為什麼明明壞三個月都沒人發現？」

那就要：

> 找 root cause → 消除原因 → 防止再發

這才是：

**矯正措施（corrective action）**

------

# 13. 內部稽核 vs 管理審查

### 內部稽核

問：

> **「我們到底有沒有照規定做？」**

要有計畫、範圍、準則、結果、改正與紀錄。教材 8.8.2 就列出這些要求。

### 管理審查

是管理層站高一層問：

> **「整套管理系統現在到底還行不行？」**

會看：

- 稽核
- 客訴
- 矯正措施
- 工作量
- 人力資源
- QC
- 風險
- 改進
- 外部評鑑……

教材 8.9 也把這些輸入項目逐一列出。

## 最終心智模型

把 ISO 17025 想成一條生產線即可：

**公正保密**
↓
**建立有權責的實驗室**
↓
**找有能力的人 + 好環境 + 正確設備 + 可追溯標準**
↓
**確認客戶需求**
↓
**選對方法**
↓
**做量測並留下原始紀錄**
↓
**算不確定度**
↓
**用 QC / PT 證明結果持續有效**
↓
**出正確報告**
↓
**客訴 / 出包就處理**
↓
**靠文件控制 + 矯正 + 稽核 + 管理審查讓系統持續運作**

**這就是 ISO/IEC 17025 的主體。**
